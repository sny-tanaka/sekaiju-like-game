# 02. 探索・マッピングシステム

担当範囲: 迷宮の3D探索 / 手描きマッピング（描画パレット・アイコン・オートパイロット）/ フロアジャンプ / 迷宮内イベント / エンカウント（エネミーアピアランス）/ 徘徊型エネミー（FOE相当）

参照元: 世界樹の迷宮Ⅴ「システム」より「探索・マッピング」「描画パレット」「アイコンパレット」「オートパイロット」「フロアジャンプ」「迷宮内イベント」「エネミーアピアランス」

> ⚠️ **[06 無限タワー構造](./06-tower-progression.md) による上書き**: 本作では迷宮を「上限のない無限階層タワー」とし、各階は **自動生成（初回入場で固定保存）** する（§2 の固定マップ前提は無限タワー向けに読み替える）。**フロアジャンプ（§4.4）は廃止し、10層ごとのワープチェックポイント（06 §5）に統合**。敵は1層ごとにスケールする（06 §3）。矛盾する場合は 06 を優先。

---

## 1. 目的・体験

世界樹の最大の独自性は **プレイヤー自身が地図を描く** こと。迷宮はグリッドで構成され、プレイヤーは一歩ずつ進みながら壁・床・宝箱・採集点・ショートカット・FOEの位置を自分で記録する。この「探索と記録」のループが体験の核。

---

## 2. 迷宮データモデル

迷宮は階層（フロア）の集合。各フロアは2Dグリッド（マス目）。プレイヤーは4方向に移動・回転する。

```ts
type Dir = 'N' | 'E' | 'S' | 'W';  // 正準定義（[05 §0.5] でも参照）

interface Cell {
  // 各辺に壁があるか（true=通行不可）。隣接セルと整合させる（A.E === B.W）
  walls: { N: boolean; E: boolean; S: boolean; W: boolean };
  floorType: FloorType;      // 通常 / ダメージ床 / 水辺 / 一方通行 / 暗闇 など
  event?: CellEventRef;      // 階段・宝箱・採集点・イベント・ショートカット等
  passable: boolean;         // そもそも侵入可能か（壁/障害物セル）
}

// セル上のオブジェクト参照（判別共用体）。実体は各ドキュメントの定義を指す
type CellEventRef =
  | { kind: 'stairsUp' }                          // 次の階への上り（[06 §4] ゲート対象）
  | { kind: 'stairsDown' }                        // 前の階への下り（入口）
  | { kind: 'chest'; chestId: string; tableId: string }  // 宝箱（開封状態は TowerFloor.openedChests）
  | { kind: 'gather'; gatherId: string }          // 採集点（[04 §5] GatheringPoint。枯渇は depletedGathers）
  | { kind: 'event'; eventId: string }            // 迷宮イベント（[02 §7] DungeonEvent。消化は consumedEvents）
  | { kind: 'cookingSpot'; spotId: string }       // 調理地点（[04 §6]）
  | { kind: 'shortcut'; shortcutId: string };     // ショートカット（扉/一方通行解除）

interface FloorMaster {
  depth: number;             // 正準キー（旧 id: string は廃止。[05 §0.5]）
  width: number;
  height: number;
  cells: Cell[][];           // [y][x]
  encounterTable: EncounterTableId; // 出現する雑魚敵プール
  foeSpawns: FoeSpawn[];     // 徘徊型エネミーの初期配置と巡回パターン
  bgmId: string;
}
```

> ⚠️ **無限タワーでは `FloorMaster` は「設計時固定の手作りマスター」ではなく `generateFloor(depth, rng)` の生成物**（[06 §2](./06-tower-progression.md)）。初回生成後に `TowerFloor.generated` として固定保存され、再訪時はそれを使う。プレイヤーが描く地図は別レイヤー `PlayerMap`（§4）として持つ。

### MVP の描画方針（グラフィックは作り込まない）

- **MVP は 2D 俯瞰のプレイヤーマップ＋軽量な擬似3D一人称ビューの2画面構成**にする。移動はマップ上のタップ／前進・回転ボタンで行う。
- **擬似3Dは採用する（MVP に含める）**が、3D/WebGL は使わず **canvas に単色＋遠近の台形だけで「正面 n マス分の壁/通路」を描く軽量実装**に留める（[README のスコープ方針](./README.md)と整合）。
  - 採用理由（ユーザー決定）: **直線上の FOE やオブジェクトを「正面に見える」形で把握する手がかり**として擬似3Dが必要。これが無いと直線上の脅威を認識できない。
  - 実装: `castView`（純関数で正面の見通しを算出）＋ `FirstPersonView`（canvas 描画）。階段等は正面にマーカー表示し、将来 FOE もここに重ねる。

### 床タイプの例（FloorType）

通常 / ダメージ床（侵入時HP減少）/ 水辺（視認はできるが進入で挙動変化）/ 暗闇（視界制限）/ 一方通行 / 滑る床 / 落とし穴 など。床色は手描きマップで色分け表現できる（§4.1）。

## 3. 移動と視界

- 移動: グリッドを1マスずつ前進、左右回転、振り向く（180度）。マップ上の隣接マスのタップでも1歩移動。
- 視界: **軽量な擬似3D一人称ビュー**（canvas に単色台形で「正面n マス分の壁/通路」を描画。3D/WebGL不使用）。リッチな3D描画はしない。
- **オートマップ**: 壁/床は**自動で踏破描画**する（後述の通り MVP では壁/床の手描きは行わない）。設定 `autoMap`（OFF / ON / FULL）で自動描画の強さを切替できる枠を持つ。

## 4. 手描きマッピング（中核機能）

プレイヤーは `<canvas>` 上で地図を自由に描ける。地図はフロアごとに保存。

> ⚠️ **MVP 方針変更（ユーザー決定）**: 当初は「壁線・床塗りを含めて全部プレイヤーが手描き」する想定だったが、**スマホ操作で壁線/床塗りを手描きするのは扱いづらい**ため、本作では次のように再定義する。
> - **壁/床はオートマップ（自動踏破描画）**に任せる（§3）。プレイヤーは壁線・床塗りを手で引かない。
> - **手動マッピングは「アイコン配置」のみ**にする（§4.2）。擬似3D（§3）で見た脅威・宝箱・近道などを、プレイヤーがマップ上のマスにアイコンで記録する。これが本作の「探索して記録する」ループの中核。
> - **壁線・床塗りの手描きパレット（§4.1）／オートパイロット（§4.3）は MVP では不採用**（将来の任意拡張）。`PlayerMap` の `floorPaint`/`wallDraw`/`autopilotRoutes` は型として枠だけ残す。
> - 実装: `domain/playerMap`（アイコンの配置/消去）＋ 探索画面のアイコンパレット。`SaveData.playerMaps[depth].icons` に保存。

### 4.1 描画パレット（壁線・床塗り）

- **床色**: 8色程度から選択し、マスを塗れる。水辺・ダメージ床など地形を色で表現。
- **壁線**: マスの辺に壁線を引く。
- オートマップON/FULL時は歩いた床・壁を自動描画。
- 色パレットはスライドで位置変更可能（UI配慮）。

### 4.2 アイコンパレット

- マップ上に配置できるアイコンを **40種程度** 用意（階段↑↓・宝箱・採集点・扉・ショートカット・FOE・注意・メモ等）。
- 採集系アイコン・宝箱アイコンは **採集/開封の進捗に応じて見た目が変化**（未採集→採集済みなど）。
- パレットは表示個数をスライド調整可能。並べ替え（ICON EDIT）でユーザーが使いやすい順にカスタムできる。

### 4.3 オートパイロット（自動巡回ルート）

プレイヤーが描いたルート線を、キャラが自動でなぞって移動する機能（探索済みフロアの再周回・採集回りを省力化）。

- ルート線を描く（実線矢印）。色違いで **1フロア最大5本**。
- ルートの両端延長（両矢印）、末尾から逆なぞりで消去（点線矢印）、長押し一括削除。
- 1本の矢印の **方向転換は18回まで**（180度転回も1回換算）。長さ制限なし。
- 往復を描くと矢印が太くなり、一本道往復や8の字ルートも表現可。
- 再生ボタンで実行。ズーム時は経路が光って見える。直前操作の取り消し可。

```ts
interface PlayerMap {
  depth: number;                   // 正準キー（[05 §0.5]。旧 floorId は廃止）
  floorPaint: (string | null)[][]; // 各マスの色ID（パレットの色ID参照）
  wallDraw: WallEdge[];            // プレイヤーが引いた壁線
  icons: PlacedIcon[];             // 配置アイコン
  notes: MapNote[];                // テキストメモ
  autopilotRoutes: AutoRoute[];    // 最大5本
}

// 壁線は「あるセルのどの辺か」で表す（線種・色つき）。隣接セルと重複させない正準化規則：
// 北/西辺は own、南/東辺は隣接セルの北/西辺として持つ（重複登録を避ける）
interface WallEdge { x: number; y: number; side: 'N' | 'W'; style?: 'solid' | 'dashed'; colorId?: string; }
interface PlacedIcon { x: number; y: number; iconId: string; }
interface MapNote { x: number; y: number; text: string; }        // 最大文字数はUIで制限
interface AutoRoute {
  colorId: string;
  points: { x: number; y: number }[]; // 折れ線。方向転換18回まで（[02 §4.3]）
}
```

> **設計判断**: プレイヤーマップは生成済み迷宮（正解の壁配置）とは独立。両者の差分が「未踏破」。踏破情報（視認セル）は `SaveData.exploredCells[depth]: string[]`（`cellKey="x,y"`、[05 §0.5](./05-progression-meta.md)）で保持し、メモリ上では `Set<cellKey>` に展開する。

### 4.4 フロアジャンプ → 廃止（10層ワープに統合）

> 🚫 **元ゲームの「マップ完成で次階へジャンプ」は本作では採用しない。** 無限タワーでは「次階へ1階ずつ解放」より、**10層ごとのワープチェックポイント**（[06 §5](./06-tower-progression.md)）の方が構造に合う。階層ボス撃破で第10・20・30…階へのワープが解放され、拠点のワープ装置から飛ぶ。マップ完成度や評議会（ストーリー組織）への提示は条件にしない。

- 拠点⇄到達済みチェックポイントのワープ仕様は [06 §5](./06-tower-progression.md) を参照。
- 帰還手段（帰還アイテム）の所持確認をUIで促す設計は引き続き有効。

## 5. エンカウント（エネミーアピアランス）

ランダムエンカウントを「いきなり」ではなく **予兆ゲージ** で可視化する親切設計。

- 画面に円形ゲージを表示。これは遭遇確率ではなく **エンカウントまでの残り歩数を5段階で示す**。
- 残り歩数はランダム。歩くごとにゲージが基本1段階ずつ進む。**ゲージが満タンになるまでエンカウントしない**（＝満タン前は安全に動ける）。
- スキル・アイテムでゲージ進行を早める/遅らせる（敵を呼ぶ/避ける）操作が可能。
- 残り歩数は **戦闘・別階移動・迷宮離脱でリセット**。

```ts
interface EncounterState {
  stepsUntilEncounter: number; // 内部値（プレイヤーには非公開）
  totalSteps: number;          // この区間で歩いた数（ゲージ段階の算出に使用）
}
function onStep(state: EncounterState, rng: Rng): { state: EncounterState; triggered: boolean };
```

**数値ルール（暫定）**:
- 区間開始時（戦闘後・階移動・離脱後）に `stepsUntilEncounter = rng.range(8, 16)` を抽選（深層でレンジを狭めて頻度を上げてもよい）。
- 1歩ごとに `stepsUntilEncounter--`。0でエンカウント発生→区間リセット。
- **ゲージ5段階表示** = 「消化率」を5分割。満タン（残り0直前）でのみ発生し、満タン前は安全。
  - 実装メモ: `DiveState.encounter` は `stepsUntilEncounter` のみを保存する（[05 §4]）。初期歩数は保存しないため、MVP のゲージは `gaugeLevel(steps)` が **最大歩数（16）に対する消化率**で 5 段階に量子化する近似実装（`domain/encounter`）。
- スキル/アイテムで `stepsUntilEncounter` を増減（敵を避ける/呼ぶ）。`diveState.encounter`（[05 §4](./05-progression-meta.md)）に保存し、同一階の移動中もオートセーブで保持される。

### 5.1 FOE距離ゲージ

- 円ゲージの横に **葉状ゲージ** が出ることがあり、FOE/ボスとの距離を示す。
- 赤葉1枚=3マス、2枚=2マス、3枚=1マス（隣接）。4マス以上は非表示。
- 壁の向こう・水辺・壁中のFOEでも表示される（位置察知の補助）。

## 6. 徘徊型エネミー（FOE相当）

迷宮内を実際に移動する強敵。ランダムエンカウントとは別枠の「見える脅威」。

### 6.1 仕様

- マップ上に常駐し、ターン（プレイヤーの1歩）ごとに巡回・追跡ロジックで移動する。
- 直線なら1ターンに複数マス移動できる個体など、移動特性に個体差。
- 接触で戦闘。序盤は格上で、回避・誘導（別のFOE/ギミックにぶつける）・条件を整えてから撃破、という攻略性を持つ。
- 一部ボスは「戦闘になるまでその場にいない」など、距離ゲージ非表示でも油断できない挙動。

### 6.2 データモデル

```ts
type PatrolPattern =
  | { kind: 'static' }                              // その場で待機（部屋番）
  | { kind: 'loop'; waypoints: { x: number; y: number }[] } // 経路巡回
  | { kind: 'wander' }                              // ランダム徘徊
  | { kind: 'charge'; dir: Dir };                   // 直線突進（壁/プレイヤーまで直進）

interface FoeSpawn {
  id: string;
  enemyId: string;
  startCell: { x: number; y: number };
  patrol: PatrolPattern;
  moveSpeed: number;       // 1ターンの最大移動マス
  sightRange: number;      // この距離以内のプレイヤーを感知し alerted へ（追跡開始）
  respawn: boolean;        // 撃破後に復活するか
}

interface FoeRuntimeState {
  spawnId: string;
  cell: { x: number; y: number };
  defeated: boolean;
  alerted: boolean;        // プレイヤーを感知して追跡中か
}
```

**移動AI（手番制・確定ルール）**: `stepFoes(floor, foes, playerPos, rng)` を純関数化。
1. FOEは **プレイヤーが1歩動くたびに `spawnId` 昇順で1体ずつ** 解決（処理順を固定）。
2. **感知**: 未 alerted のFOEは、プレイヤーが `sightRange` 以内かつ壁で遮られなければ `alerted=true`（追跡へ）。
3. **追跡（alerted）**: プレイヤー方向へ最短1歩（BFS/貪欲、壁・`passable=false` を考慮）。`moveSpeed` 分まで移動し、途中でプレイヤーセルに到達したら **接触＝戦闘**（接触方向で先制/不意打ち判定、[03 §10](./03-battle-system.md)）。
4. **非追跡**: `patrol` に従う（loop は次waypointへ、wander はランダム隣接、charge は直進、static は不動）。
5. **衝突**: FOE同士は同一セルに重ならない（先着優先で停止）。`charge` 中のFOEが別FOEや壁に当たると停止（誘導・ぶつけ合いの基礎）。
6. **床タイプ**: FOEはダメージ床等の特殊床効果を受けない（プレイヤー専用ギミックとして扱う。MVP簡略化）。

> **設計判断**: 「プレイヤー1歩＝全FOE1手」の手番制でパズル性を出す。乱数（wander等）は `rng` 注入でテスト再現可能に。

## 7. 迷宮内イベント

迷宮内で発生する小イベント・アクシデント・他冒険者との遭遇など。

- 小イベント終了時に **まとめ文＋経験値獲得** を表示。
- **選択肢で経験値や入手アイテムが増減**する（分岐）。
- イベント経験値は **戦闘不能のキャラにも均等配分**（救済・後衛育成）。
- イベントの達成・報酬増加に **特定の種族スキル（探索系）** が必要なことがある → 戦闘スキルだけでなく探索スキルにもSPを割く動機。

```ts
interface DungeonEvent {
  id: string;
  triggerCell: { x: number; y: number };
  text: string;
  choices: EventChoice[];
  oneShot: boolean; // 一度きりか
}
interface EventChoice {
  label: string;
  requiredSkill?: string;   // この種族スキル保持時のみ成功/好結果
  rewardExp: number;
  rewardItems?: ItemStack[];
  resultText: string;
}
```

## 8. 採集（探索リソース獲得）

迷宮の採集ポイントから素材を得る。詳細な品目は [04 アイテム](./04-items-equipment-crafting.md) で扱うが、探索側の接点として：

- 採集ポイントは特定スキル保持者がいると有効化される（採掘/採取/伐採、加えて釣り/収穫/狩猟など食材系）。
- 採集済みアイコンは見た目が変化（§4.2）。
