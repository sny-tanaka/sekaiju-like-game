# 01. キャラクター・ギルドシステム

担当範囲: キャラメイク / 種族 / 職業 / レベル・SP / 転職 / 転生 / 称号（二つ名）/ ギルド管理

参照元: 世界樹の迷宮Ⅴ「システム」より「キャラクターメイク」「冒険者の登録」「転職」「引退（本作では『転生』に改称）」「二つ名習得」

---

## 1. 目的・体験

プレイヤーは自分でキャラクターを作成し、ギルドに登録してパーティを編成する。**種族 × 職業 × スキル振り × 称号** の膨大な組み合わせから自分だけのパーティを構築できることが育成の核。育成は「レベルアップによるステータス成長」と「SPによるスキル習得」の二軸で進む。

---

## 2. キャラクターメイク

### 2.1 機能要件

- ギルドに新規キャラクターを作成・登録できる。上限人数（例: 30人）まで。
- 作成時に決める要素:
  - **種族**（基本ステータスとユニオンスキルを規定）
  - **職業**（スキルツリー・装備適性を規定）。**種族と職業はそれぞれ独立に自由選択できる**（既定職業への固定はしない）。ただし一部の職業は **特定階層への到達などの解放条件** を持つ場合がある（解放前は作成時の選択肢に出さない。条件付き職業の具体は今後定義しうる）。
  - **名前**
- **作成後の再編集**: 名前は管理画面からいつでも変更可能（種族・基本ステータスは不変）。

> **本作の方針**: 自作ゲームでありグラフィックは作り込まないため、元ゲームにあった外見カスタマイズ（立ち絵・髪/目/肌の色）やボイス選択といった **飾り要素は実装しない**。キャラクターはアイコン（または簡易な見た目区分）と名前で識別する程度に留め、ゲームメカニクス（種族・職業・スキル）に注力する。将来的に見た目を足す場合は、職業/種族ごとの固定アイコン差し替えで十分とする。

### 2.2 データモデル（TypeScript）

```ts
type RaceId = string;   // マスターデータのキー
type ClassId = string;

interface Character {
  id: string;
  name: string;
  raceId: RaceId;          // 不変（作成時に確定）
  classId: ClassId;        // 転職で変更される
  titleId: ClassId | null; // 称号（第2スキルツリー）。未習得は null
  level: number;
  exp: number;
  baseStats: Stats;        // 種族と現Lvから算出される素のステータス
  skillPoints: { total: number; spent: number };
  learnedSkills: Record<string, number>; // skillId -> 習得Lv
  equipment: EquipmentSlots;
  rebirthBonus?: RebirthBonus;            // 転生由来の補正（後述）
}
```

> `Stats` の正準定義は [05 §0.1](./05-progression-meta.md)。`baseStats` は保存値ではなく純関数で導出する。**ステータス算出パイプライン（責務分離）**:
>
> 1. `computeBaseStats(char): Stats` — 種族成長テーブル × Lv ＋ 転生ボーナス ＋ 称号 `growthModifier`（[§8](#8-称号-二つ名--第2スキルツリー)）。素質のみ。
> 2. `deriveCombat(stats, equip, buffs): DerivedCombat`（[05 §0.2](./05-progression-meta.md)・[03 §7](./03-battle-system.md)）— 装備 `EquipBonuses`・バフを乗せ、戦闘用の patk/pdef/matk/mdef/命中/回避/クリを算出。
>
> 保存するのは `level`/`exp`/`learnedSkills`/`equipment`/`rebirthBonus` 等の「入力」だけで、`Stats`・`DerivedCombat` は常に導出（セーブに持たない）。

## 3. 種族（Race）

### 3.1 仕様

- **基本ステータスは職業ではなく種族で決まる**。種族ごとに成長傾向（HP寄り・TP寄り・STR寄り…）が異なる。
- 各種族は固有の **種族スキル**（探索系スキルや**ユニオンスキル**などを含むスキルツリー）を持つ。種族スキルは転職しても **変更されない**（作成時のまま）。
- 種族の例（本作オリジナルで命名する。元ゲームの種族名は使わない）:
  - バランス型ヒューマン系 / 物理特化の大型種 / 魔法特化の小型種 / 獣使い種 など3〜5種族程度をMVP想定。

### 3.2 マスターデータ構造

```ts
interface RaceMaster {
  id: RaceId;
  name: string;
  statGrowth: StatGrowth;       // Lvごとの各能力上昇量
  baseStatsAtLv1: Stats;
  unionSkillTree: SkillTreeDef; // 種族固有（ユニオンスキル含む）
}
```

> **編成の指針**: 種族によって使えるユニオンスキルが変わるため、パーティの種族構成自体が戦略になる（[03 バトル](./03-battle-system.md) 参照）。

## 4. 職業（Class）

### 4.1 仕様

- 職業は **スキルツリー（基本スキル＋達人スキル）** と **装備適性** を規定する。
- **キャラ作成時に種族と職業を独立に自由選択できる**（種族ごとの既定職業に固定しない）。種族とのミスマッチ（防御の低い種族を前衛職に等）は戦術的トレードオフとして許容する。
- ただし職業ごとに **解放条件**（例: 特定階層への到達履歴）を設定できる設計とする。解放前の職業は作成・転職の選択肢に出さない。MVP の基本職業はすべて初期から選択可能で、条件付き職業は今後追加しうる。
- **転職** は既存キャラの職業を別の **解放済み職業** に変更する機能（[§6](#6-転職-class-change)）。職業選択自体に全体的な到達階ゲートは設けない（解放はあくまで職業単位）。

### 4.2 マスターデータ構造

```ts
interface ClassMaster {
  id: ClassId;
  name: string;
  skillTree: SkillTreeDef;          // 基本スキル + 達人スキル
  equipableWeaponTypes: WeaponType[];
  equipableArmorTypes: ArmorType[];
  titleOptions: [ClassId, ClassId]; // この職業が選べる称号2種（後述）
}
```

## 5. レベル・経験値・SP

- 戦闘・迷宮イベントで経験値を獲得しレベルアップ。レベルアップで `baseStats` が成長し、**SP（スキルポイント）** を得る。
- **成長式（形は確定・係数は暫定、[06 §3.1 `BALANCE`](./06-tower-progression.md)）**:
  - 素ステは線形: `stat(Lv) = baseStatsAtLv1[k] + statGrowth[k] * (Lv - 1)`（敵も線形スケールなので相対関係を保ちやすい）。
  - 経験値: `expToNext(Lv) = round(EXP_CURVE_BASE * Lv^EXP_CURVE_POW)`（逓増）。
  - レベルアップ時の獲得SP: 固定（例 +3／Lv、暫定）。
- **レベル上限は100**（`LEVEL_CAP = 100`）。上限到達後は経験値を得てもレベルは上がらない。さらなる強化は **転生**（§7）でリセット＆ボーナス獲得、装備・鍛冶（[04](./04-items-equipment-crafting.md)）、スキル振り直しで行う。転生システムがあるため、青天井にはせず上限を設けることで「100到達→転生で作り直し」という育成サイクルを成立させる。
- SPは基本/達人/種族/称号の各スキルツリーに振り分けてスキルを習得・強化する。レベル上限が100のため取得SPも有限で、全スキル取得には複数回の転生（ボーナスSP）が必要になる設計にできる。
- **迷宮イベント由来の経験値は戦闘不能のキャラにも均等配分**される（後衛育成・全滅回避救済の設計。[02 探索](./02-exploration-mapping.md) 参照）。

> レベル上限・敵スケーリングとの関係は [06 無限タワー構造](./06-tower-progression.md) を参照。

## 6. 転職（Class Change）

### 6.1 仕様

- 対象職業: **解放済みの職業のみ**に変更できる（職業ごとの解放条件は [§4.1](#41-仕様) / [06 §8](./06-tower-progression.md)）。転職機能そのものに全体的な到達階ゲートは設けない。※ストーリーミッションは無い。
- 変更されるもの: **職業**（基本スキル・達人スキル・装備適性）。
- 変更されないもの: **種族・種族スキル・基本ステータス傾向**。
- **コスト/ペナルティ**: 転職するとレベルが一定値（例: -5）下がる。SP振り直しが発生。
- 注意設計: 防御の低い種族を前衛職にすると打たれ弱くなるなど、**種族とのミスマッチが戦術的トレードオフ**になる。

### 6.2 処理フロー

```
transferClass(char, newClassId):
  assert(機能が解放済み)
  char.classId = newClassId
  char.level = max(1, char.level - LEVEL_PENALTY)  // 経験値も該当Lvに合わせて再計算
  reset(char.learnedSkills の 旧職業ツリー分)        // 種族スキルは保持
  recompute(char.skillPoints)                        // 振り直し可能に
```

## 7. 転生（Rebirth）

> 元ゲームの「引退」に相当するシステムを、本作では **転生** と呼ぶ。レベル上限（100）に達したキャラを作り直して強い新人として再育成する、育成サイクルの軸。

### 7.1 仕様

- 条件: **レベル30以上**のキャラ（レベル上限100まで、いつでも転生可能）。
- 効果: そのキャラを消去し、新しいキャラを一から作り直す（キャラメイク同様）。**転生元のキャラメイク設定は引き継げない**。
- 報酬: 転生時のレベルに応じて、新キャラに **ステータス上昇ボーナス** と **SPボーナス** が付与される。新キャラの開始レベルは転生時の半分（上限30）。
- ボーナスは **累積しない**（直前の転生ボーナスのみ反映）。転生後に休養しても維持される。同名キャラの再採用も可。

### 7.2 転生ボーナステーブル

| 転生時Lv | 全能力上昇 | SP上昇 | 総SP（目安） |
| --- | --- | --- | --- |
| 30〜34 | +2 | +4 | Lv+6 |
| 35〜39 | +3 | +4 | Lv+6 |
| 40〜44 | +4 | +5 | Lv+7 |
| 45〜49 | +5 | +5 | Lv+7 |
| 50〜54 | +6 | +6 | Lv+8 |
| 55〜59 | +7 | +6 | Lv+8 |
| 60〜64 | +8 | +7 | Lv+9 |
| 65〜69 | +9 | +7 | Lv+9 |
| 70〜99 | +10 | +8 | Lv+10 |
| 100（上限） | +20 | +10 | Lv+12 |

```ts
interface RebirthBonus {
  allStats: number;  // 全能力に加算
  bonusSp: number;   // 追加SP
}
function reincarnate(char: Character): Character /* 新規キャラ */ {
  const bonus = lookupRebirthBonus(char.level); // 直前転生分のみ反映（累積しない）
  const startLv = Math.min(30, Math.floor(char.level / 2));
  // 新キャラ作成。bonus を反映して開始
}
```

> **設計意図**: レベル上限100に達した（あるいは達する前の）キャラを「強い新人」に作り替える育成リセット要素。レベル上限と組み合わせることで「100まで育てる → 転生で作り直し、ボーナスで素の強さを底上げ」という反復育成サイクルを作る。無限タワー（[06](./06-tower-progression.md)）でより深く登るための恒常的な強化手段。

## 8. 称号（二つ名 / 第2スキルツリー）

### 8.1 仕様

- 進行で解放される拡張システム。1職業につき **2種類の称号** から1つを選び、**新たなスキルツリーを追加**できる。
- 称号によって **その後のステータス成長傾向が変化**する（例: 回避特化称号→AGI中心成長 / 連撃特化称号→STR中心成長）。
- 称号習得時に **SP+5** のボーナス。
- 称号名はプレイヤーが任意編集可能（例: 15文字以内）。

### 8.2 データ反映

```ts
interface TitleMaster {
  id: ClassId;            // 称号ID
  name: string;
  parentClassId: ClassId; // どの職業の称号か
  skillTree: SkillTreeDef;
  growthModifier: StatGrowth; // 成長傾向の補正
}
// Character.titleId に格納。baseStats算出時に growthModifier を合成
```

> **設計意図**: 同じ職業でもビルドを2方向に分岐させ、構築の幅を倍にする。元ゲームのサブクラス相当のやり込み要素。

## 9. ギルド管理

### 9.1 仕様

- ギルドは登録キャラ一覧・所持金・図鑑・倉庫（預かり所）を束ねる単位。ギルド名を持つ。
- 拠点（街）で行える管理:
  - キャラ作成 / 編集（名前）/ 転職 / 転生 / 称号習得
  - パーティ編成（出撃メンバー選択と隊列指定）
  - 休養（後述の救済・調整。転生ボーナスは維持される）
- **ギルドカード（任意）**: 自ギルドの記録カード（ギルド名・到達記録・編成など）。元ゲームの QR 共有や周回引き継ぎは本作では非対象（周回・NG+ は無い、[05 §3](./05-progression-meta.md)）。実装するなら「到達記録の表示／画像エクスポート」程度の任意機能に留める。

### 9.2 データモデル

```ts
interface Guild {
  name: string;
  gold: number;
  members: Character[];          // 上限あり（例: 30）
  party: PartyFormation;         // 出撃中の編成
  storage: ItemStack[];          // 預かり所
  bestiary: BestiaryState;       // 図鑑
}

interface PartyFormation {
  front: (string | null)[];      // 前衛スロット（characterId）
  back: (string | null)[];       // 後衛スロット
}
```
