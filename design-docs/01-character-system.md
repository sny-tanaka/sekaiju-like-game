# 01. キャラクター・ギルドシステム

担当範囲: キャラメイク / 種族 / 職業 / レベル・SP / 転職 / 引退 / 称号（二つ名）/ ギルド管理

参照元: 世界樹の迷宮Ⅴ「システム」より「キャラクターメイク」「冒険者の登録」「転職」「引退」「二つ名習得」

---

## 1. 目的・体験

プレイヤーは自分でキャラクターを作成し、ギルドに登録してパーティを編成する。**種族 × 職業 × スキル振り × 称号** の膨大な組み合わせから自分だけのパーティを構築できることが育成の核。育成は「レベルアップによるステータス成長」と「SPによるスキル習得」の二軸で進む。

---

## 2. キャラクターメイク

### 2.1 機能要件

- ギルドに新規キャラクターを作成・登録できる。上限人数（例: 30人）まで。
- 作成時に決める要素:
  - **種族**（基本ステータスとユニオンスキルを規定）
  - **職業**（スキルツリー・装備適性を規定）※物語序盤は種族に職業が紐づき、組み合わせで迷わせない。中盤の転職解放後に自由化
  - **名前**
- **作成後の再編集**: 名前は管理画面からいつでも変更可能（種族・基本ステータスは不変）。

> **本作の方針**: 自作ゲームでありグラフィックは作り込まないため、元ゲームにあった外見カスタマイズ（立ち絵・髪/目/肌の色）やボイス選択といった **飾り要素は実装しない**。キャラクターはアイコン（または簡易な見た目区分）と名前で識別する程度に留め、ゲームメカニクス（種族・職業・スキル）に注力する。将来的に見た目を足す場合は、職業/種族ごとの固定アイコン差し替えで十分とする。

### 2.2 データモデル（TypeScript）

```ts
type RaceId = string;   // マスターデータのキー
type ClassId = string;

interface Character {
  id: string;
  name: string;
  raceId: RaceId;          // 不変（作成時に確定）
  classId: ClassId;        // 転職で変更される
  titleId: ClassId | null; // 称号（第2スキルツリー）。未習得は null
  level: number;
  exp: number;
  baseStats: Stats;        // 種族と現Lvから算出される素のステータス
  skillPoints: { total: number; spent: number };
  learnedSkills: Record<string, number>; // skillId -> 習得Lv
  equipment: EquipmentSlots;
  retirementBonus?: RetirementBonus;      // 引退由来の補正（後述）
}
```

> `baseStats` は保存値ではなく「種族成長テーブル × Lv（＋引退ボーナス）」から導出する純関数 `computeBaseStats(char)` にするのが望ましい。装備・バフを足した最終値は戦闘時にさらに別関数で算出。

## 3. 種族（Race）

### 3.1 仕様

- **基本ステータスは職業ではなく種族で決まる**。種族ごとに成長傾向（HP寄り・TP寄り・STR寄り…）が異なる。
- 各種族は固有の **種族スキル**（探索系スキルや**ユニオンスキル**などを含むスキルツリー）を持つ。種族スキルは転職しても **変更されない**（作成時のまま）。
- 種族の例（本作オリジナルで命名する。元ゲームの種族名は使わない）:
  - バランス型ヒューマン系 / 物理特化の大型種 / 魔法特化の小型種 / 獣使い種 など3〜5種族程度をMVP想定。

### 3.2 マスターデータ構造

```ts
interface RaceMaster {
  id: RaceId;
  name: string;
  statGrowth: StatGrowth;       // Lvごとの各能力上昇量
  baseStatsAtLv1: Stats;
  unionSkillTree: SkillTreeDef; // 種族固有（ユニオンスキル含む）
}
```

> **編成の指針**: 種族によって使えるユニオンスキルが変わるため、パーティの種族構成自体が戦略になる（[03 バトル](./03-battle-system.md) 参照）。

---

## 4. 職業（Class）

### 4.1 仕様

- 職業は **スキルツリー（基本スキル＋達人スキル）** と **装備適性** を規定する。
- 序盤は種族ごとに既定職業が割り当てられ、組み合わせ選択は発生しない。
- 中盤、最初のミッション達成で **転職** が解放され、種族を問わず別職業に変更可能になる。

### 4.2 マスターデータ構造

```ts
interface ClassMaster {
  id: ClassId;
  name: string;
  skillTree: SkillTreeDef;          // 基本スキル + 達人スキル
  equipableWeaponTypes: WeaponType[];
  equipableArmorTypes: ArmorType[];
  titleOptions: [ClassId, ClassId]; // この職業が選べる称号2種（後述）
}
```

## 5. レベル・経験値・SP

- 戦闘・迷宮イベントで経験値を獲得しレベルアップ。レベルアップで `baseStats` が成長し、**SP（スキルポイント）** を得る。
- SPは基本/達人/種族/称号の各スキルツリーに振り分けてスキルを習得・強化する。
- **迷宮イベント由来の経験値は戦闘不能のキャラにも均等配分**される（後衛育成・全滅回避救済の設計。[02 探索](./02-exploration-mapping.md) 参照）。

---

## 6. 転職（Class Change）

### 6.1 仕様

- 解放条件: 序盤の特定ミッションクリア。
- 変更されるもの: **職業**（基本スキル・達人スキル・装備適性）。
- 変更されないもの: **種族・種族スキル・基本ステータス傾向**。
- **コスト/ペナルティ**: 転職するとレベルが一定値（例: -5）下がる。SP振り直しが発生。
- 注意設計: 防御の低い種族を前衛職にすると打たれ弱くなるなど、**種族とのミスマッチが戦術的トレードオフ**になる。

### 6.2 処理フロー

```
transferClass(char, newClassId):
  assert(機能が解放済み)
  char.classId = newClassId
  char.level = max(1, char.level - LEVEL_PENALTY)  // 経験値も該当Lvに合わせて再計算
  reset(char.learnedSkills の 旧職業ツリー分)        // 種族スキルは保持
  recompute(char.skillPoints)                        // 振り直し可能に
```

## 7. 引退（Retirement）

### 7.1 仕様

- 条件: **レベル30以上**のキャラ。
- 効果: そのキャラを消去し、新しいキャラを一から作り直す（キャラメイク同様）。**引退元のキャラメイク設定は引き継げない**。
- 報酬: 引退時のレベルに応じて、新キャラに **ステータス上昇ボーナス** と **SPボーナス** が付与される。新キャラの開始レベルは引退時の半分（上限30）。
- ボーナスは **累積しない**（直前の引退ボーナスのみ反映）。引退後に休養しても維持される。同名キャラの再採用も可。

### 7.2 引退ボーナステーブル

| 引退時Lv | 全能力上昇 | SP上昇 | 総SP（目安） |
| --- | --- | --- | --- |
| 30〜34 | +2 | +4 | Lv+6 |
| 35〜39 | +3 | +4 | Lv+6 |
| 40〜44 | +4 | +5 | Lv+7 |
| 45〜49 | +5 | +5 | Lv+7 |
| 50〜54 | +6 | +6 | Lv+8 |
| 55〜59 | +7 | +6 | Lv+8 |
| 60〜64 | +8 | +7 | Lv+9 |
| 65〜69 | +9 | +7 | Lv+9 |
| 70〜98 | +10 | +8 | Lv+10 |
| 99 | +20 | +10 | Lv+12 |

```ts
interface RetirementBonus {
  allStats: number;  // 全能力に加算
  bonusSp: number;   // 追加SP
}
function retire(char: Character): Character /* 新規キャラ */ {
  const bonus = lookupRetirementBonus(char.level);
  const startLv = Math.min(30, Math.floor(char.level / 2));
  // 新キャラ作成。bonus は直前引退分のみ反映（累積しない）
}
```

> **設計意図**: 高レベルキャラを「強い新人」に作り替える育成リセット要素。終盤の戦力底上げ・縛りプレイ・キャラメイクやり直しの導線になる。

## 8. 称号（二つ名 / 第2スキルツリー）

### 8.1 仕様

- 進行で解放される拡張システム。1職業につき **2種類の称号** から1つを選び、**新たなスキルツリーを追加**できる。
- 称号によって **その後のステータス成長傾向が変化**する（例: 回避特化称号→AGI中心成長 / 連撃特化称号→STR中心成長）。
- 称号習得時に **SP+5** のボーナス。
- 称号名はプレイヤーが任意編集可能（例: 15文字以内）。

### 8.2 データ反映

```ts
interface TitleMaster {
  id: ClassId;            // 称号ID
  name: string;
  parentClassId: ClassId; // どの職業の称号か
  skillTree: SkillTreeDef;
  growthModifier: StatGrowth; // 成長傾向の補正
}
// Character.titleId に格納。baseStats算出時に growthModifier を合成
```

> **設計意図**: 同じ職業でもビルドを2方向に分岐させ、構築の幅を倍にする。元ゲームのサブクラス相当のやり込み要素。

## 9. ギルド管理

### 9.1 仕様

- ギルドは登録キャラ一覧・所持金・図鑑・倉庫（預かり所）を束ねる単位。ギルド名を持つ。
- 拠点（街）で行える管理:
  - キャラ作成 / 編集（名前）/ 転職 / 引退 / 称号習得
  - パーティ編成（出撃メンバー選択と隊列指定）
  - 休養（後述の救済・調整。引退ボーナスは維持される）
- **ギルドカード**: 自ギルドの紹介データ。周回引き継ぎ対象（[05 メタ進行](./05-progression-meta.md) 参照）。

### 9.2 データモデル

```ts
interface Guild {
  name: string;
  gold: number;
  members: Character[];          // 上限あり（例: 30）
  party: PartyFormation;         // 出撃中の編成
  storage: ItemStack[];          // 預かり所
  bestiary: BestiaryState;       // 図鑑
}

interface PartyFormation {
  front: (string | null)[];      // 前衛スロット（characterId）
  back: (string | null)[];       // 後衛スロット
}
```
