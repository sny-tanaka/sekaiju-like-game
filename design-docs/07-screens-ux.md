# 07. 画面・拠点・操作・初回フロー（UX）

担当範囲: 画面遷移フロー全体 / 拠点（街）の機能集約 / 操作・入力仕様 / 初回起動フロー / セーブUI / オーディオ・i18n・PWA のスコープ方針

> レビューで「拠点画面の全体像・画面遷移図・操作/入力仕様・初回フロー」が章レベルで欠落と指摘されたため新設。01〜06 に散在する UI 接点をここに集約する。

## 1. 画面遷移フロー全体

```
[タイトル/スロット選択]
   │ 新規 → §4 初回フロー → [拠点]
   │ 続き(ロード) ─────────→ [拠点]（diveState!=null なら「潜行を再開しますか？」）
   ▼
[拠点 (Town)] ←──────────────────────────┐
   ├─ ギルド管理（編成/キャラ作成/転職/転生/称号/スキル振り）
   ├─ ショップ / 鍛冶 / 料理レシピ / 飼育
   ├─ 図鑑 / 到達記録
   └─ ワープ装置 →┐
[ダイブ開始]      │（第1階 or 解放済みチェックポイントを選択）
   ▼             │
[探索 (Dungeon)] ─┤ 帰還アイテム/階段で拠点へ
   ├─ エンカウント/FOE接触 → [戦闘 (Battle)] → 勝(探索へ) / 全滅(§全滅→拠点)
   ├─ 階段で上下移動（ボス階ゲートは [06 §4]）
   └─ メニュー（アイテム/状態/マップ/設定/帰還）
```

- ルーティング（React Router 7）: `/title` `/town` `/dungeon` `/battle`（または戦闘はモーダル）。`/town` 配下に施設サブ画面。
- **戦闘の戻り先**: 勝利＝直前の探索状態（`diveState`）へ復帰。全滅＝[06 §6](./06-tower-progression.md) のソフトペナルティ処理（`diveState=null`、拠点へ）。

## 2. 拠点（街）の機能集約

各ドキュメントに散在する拠点施設を一覧化。拠点画面はこれらへの導線を持つハブ。

| 施設 | 機能 | 参照 |
| --- | --- | --- |
| ギルド受付 | キャラ作成 / 編集(名前) / 転職 / 転生 / 称号習得 / スキル振り / 編成 | [01](./01-character-system.md) |
| ショップ | 装備・アイテム売買、素材売却で品揃え解放（ティア） | [04 §8](./04-items-equipment-crafting.md) |
| 鍛冶屋 | 武器強化（+5まで）/ リサイクル / インゴット変換 | [04 §4](./04-items-equipment-crafting.md) |
| 調理 | レシピで料理作成（※迷宮内の調理地点でも可、[04 §6](./04-items-equipment-crafting.md)） | [04 §6](./04-items-equipment-crafting.md) |
| 飼育（宿屋） | 捕獲した動物を預けて副産物を得る（時間概念は §下記の注意） | [04 §5](./04-items-equipment-crafting.md) |
| ワープ装置 | 解放済みチェックポイント（10/20/…階）へワープ、第1階から潜る | [06 §5](./06-tower-progression.md) |
| 図鑑 / 記録 | 図鑑閲覧・登録報酬 / 到達記録(TowerRecord)の表示 | [05](./05-progression-meta.md)・[06 §7](./06-tower-progression.md) |

> ⚠️ **「時間（日数）」概念の確定が必要**: 飼育の副産物・採集点の枯渇回復が「日数」を前提にしている（[04](./04-items-equipment-crafting.md)）が、無限タワーに暦は無い。**代替の時計**を決める（案: ①ダイブ回数 ②累計歩数 ③累計戦闘数）。推奨は「ダイブ回数」を擬似的な日数として使う。MVP では飼育・枯渇回復を省略してもよい。

## 3. 操作・入力仕様

PWA 前提なので **マウス/キーボードとタッチの両対応** を基本にする（MVP はマウス/キーボード優先でも可、ただしタッチで詰まない設計に）。

### 3.1 探索
- 移動: キーボード（`W/A/S/D` または矢印で前進・後退・左右回転）、タッチ/クリックは **マップ上のセルをタップで隣接1歩移動**、回転ボタン。
- 1歩ごとに FOE が1手動く（[02 §6](./02-exploration-mapping.md)）ため、入力は「1ステップ確定」型（押しっぱなしの連続移動は1歩ずつ解決）。

### 3.2 手描きマップ（`<canvas>`）
- モード切替: 床塗り / 壁線 / アイコン配置 / メモ / オートパイロット / 消しゴム（[02 §4](./02-exploration-mapping.md)）。
- 操作: ドラッグで塗り/線引き、タップでアイコン配置、ピンチ/ホイールでズーム、長押しで一括削除（オートパイロット）。
- Undo（直前操作取り消し）必須。

### 3.3 戦闘
- 一括入力（[03 §2](./03-battle-system.md)）: 各キャラのコマンドを順に選択 → 一括解決。
- コマンド: 攻撃 / スキル / アイテム / 防御 / 逃走 / ユニオン。キーボードとクリック/タップ両対応。

### 3.4 共通
- メニュー開閉、決定/キャンセル、ヘルプ。キーバインドは設定で変更可能にすると望ましい（MVP は固定でも可）。

## 4. 初回起動フロー（ニューゲーム）

```
[タイトル] → [最初から]（既存セーブがあれば確認ダイアログ） → ギルド名入力
   → createInitialSaveData(guildName) で初期セーブ作成（団員0人。[05 §4.1]）
   → [拠点] → ギルドで冒険者を作成（種族・職業を自由選択。最大5人）→ 編成
   → ワープ装置/ダイブで第1階へ
```

- **初期パーティ方針（確定・ユーザー決定）**: 初回は **団員 0 人**で開始する。タイトルではギルド名のみ入力し、拠点の **ギルドメニューでプレイヤーが種族・職業を選んで作成**する（自動生成はしない）。団員が 0 人の間はギルドメニュー以外（ダイブ・ショップ等）は使えない。
- **チュートリアル**: 専用ステージは作らず、第1〜2階で操作ヒントを出す軽量方式（任意）。完全スキップ可。
- **確定済み**: 初期団員 0 人 / 種族・職業は作成時に自由選択（[01 §4](./01-character-system.md)）/ `STARTING_GOLD = 500` / 出撃パーティ最大5人。作成直後は装備なし。

## 5. 全滅・帰還時の画面挙動

- 全滅 → 「ギルドは命からがら拠点へ帰還した」等の演出 → 拠点。失うのは `diveState`（[06 §6](./06-tower-progression.md)）。
- 次回ダイブはワープ装置から最深チェックポイント or 第1階を選んで再開。
- ベスト更新時（最深到達/ボス撃破）は記録更新の演出を出す（スコアアタックの動機付け、[06 §9-9](./06-tower-progression.md)）。

## 6. セーブ UI

- **セーブは1つ（確定）**: 複数スロットは持たない。タイトルにセーブの**メタ表示**（ギルド名・最高到達階・団員数・最終セーブ時刻）と「つづきから」を出す。「最初から」は**既存セーブがある場合のみ確認ダイアログ**を挟んで上書きする（無ければそのまま新規作成）。
- **オートセーブ**: 契機は [05 §4](./05-progression-meta.md) に確定（拠点帰還/階移動/ボス撃破/全滅後）。アイコンのセルフマッピングも配置時に保存。セーブ中インジケータを出す。
- **手動セーブ**: 任意（拠点でのみ許可など）。ロスト無しなので必須ではない。
- **破損時**: ロード失敗・未知バージョンは「破損」表示し、新規開始へ誘導（既存セーブは上書きしない、[05 §4.2](./05-progression-meta.md)）。

## 7. スコープ方針（オーディオ / i18n / PWA / アクセシビリティ）

実装の肥大化を防ぐため、周辺領域の「どこまでやるか」を先に固定する。

| 領域 | MVP 方針 |
| --- | --- |
| **オーディオ** | **任意（後回し）**。`FloorMaster.bgmId`（[02](./02-exploration-mapping.md)）と `GameSettings` の音量（[05 §4.2](./05-progression-meta.md)）は枠だけ残す。実装するなら帯ごとBGM＋最小SE。ブラウザの autoplay 制約のため、初回ユーザー操作後に再生開始する。 |
| **i18n / 文言** | **MVP は日本語直書き**。多言語対応は対象外。マスターデータの `name` は日本語文字列を直接持つ（将来 i18n 化する場合はキー化が必要、という点だけ認識しておく）。 |
| **PWA** | **オフライン起動＋セーブ**までは対応（テンプレの `vite-plugin-pwa` 活用）。インストール導線（A2HS プロンプト）は任意。 |
| **アクセシビリティ** | 床タイプを色のみで区別しない（**色＋アイコン/パターン併用**）。最低限のキーボード操作を確保。詳細対応は後回し。 |

## 8. MVP の縦スライス（Phase 0→1 で「動くもの」）

> 横（機能網羅）より縦（最小で遊べる一連）を先に通す。

**Phase 0（基盤）**: `SaveData`／`Rng`／IndexedDB セーブ・ロード／マスターデータ駆動の土台／`createInitialSaveData`／ルーティング。
**Phase 1（探索の縦スライス＝最初に遊べる状態）※実装済み**:
1. タイトル→最初から→ギルド名→拠点でキャラ作成（種族・職業を選択）→第1階ダイブ
2. `generateFloor(1)` の自動生成1階をグリッド移動（**2D俯瞰オートマップ＋軽量擬似3D一人称ビュー**の2画面）
3. 壁/床は**オートマップ**（自動踏破描画）、プレイヤーは**アイコンを手動配置**してセルフマッピング（壁線/床塗りの手描きは MVP 不採用、[02 §4](./02-exploration-mapping.md)）
4. エンカウントゲージ→**ダミー戦闘画面**へ遷移（戦闘ロジックは Phase 2 で本実装）
5. 階段で上下移動／帰還で拠点へ／オートセーブ・ロードで再開

この5ステップが通れば「探索して地図に印を付け、また続きから遊べる」体験が成立する。戦闘の中身（Phase 2）・育成（Phase 3）・拡張（Phase 4）・メタ（Phase 5）はこの土台に積む。
